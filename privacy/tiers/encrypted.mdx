Encrypted is the top rung of the [privacy ladder](/privacy/tiers) and the strongest privacy Nito offers. It keeps everything [Confidential](/privacy/tiers/confidential) gives you (the sealed, attestable execution of a Trusted Execution Environment) and adds end-to-end encryption: your data is encrypted on your side so it can be read only inside the sealed environment itself. In exchange, Encrypted carries the most constraints of any level. It is the choice for maximum assurance, used only where the call genuinely needs it.

<Note>
**Encrypted is not yet available in the plugin.** Today the plugin reaches up to [Confidential](/privacy/tiers/confidential), the strongest level you can select right now. Encrypted is documented here so the privacy ladder is complete and you can see where it leads.
</Note>

## What Encrypted Adds Over Confidential

Confidential runs your call inside a TEE and lets you verify it ran there. Encrypted keeps that and adds **client-side end-to-end encryption to the sealed environment**. Rather than relying on transport security up to the edge of the system, your data is encrypted so that it can be decrypted only inside the sealed TEE that runs the computation. That is what end-to-end encryption to the sealed environment means: the protection extends from your side all the way to the attested environment, not just to the system's edge.

This is the maximum-assurance posture. It is also the most constrained, because encrypting end-to-end to a sealed box rules out any feature that would need to read or transform your request along the way.

## What Encrypted Requires

Encrypted runs on specific sealed-compute backends only, and only for models that carry it. Because end-to-end encryption sits on top of sealed, attested execution, a model must already qualify for Confidential before it can offer Encrypted. The catalog marks which models offer Encrypted; the level follows the model, so you would reach it by choosing an Encrypted-level model, just as you choose any other level.

## The Constraints on Encrypted

Encrypted is non-streaming and supports a deliberately narrow feature set. When a call runs at Encrypted, these behaviors are not available:

- **Streaming.** End-to-end encryption to the sealed environment is **non-streaming** by design. Output arrives as a single complete response rather than token by token.
- **Reasoning.**
- **Tools.**
- **Prompt caching.**
- **Multi-part messages.**

If you need any of the features above, or you need streaming, use [Confidential](/privacy/tiers/confidential) instead, which keeps attested execution while supporting streaming and the normal feature set. Encrypted trades those away for the strongest protection. As with every level, a request that cannot be served at Encrypted fails with a clear message rather than dropping to a weaker level.

## How Encrypted Would Be Selected

There would be no privacy flag for Encrypted. As with every level, the level follows the model: you would browse with the `models` command, find a model that carries Encrypted, and set it with `model` (or `--model`). Because the plugin does not reach Encrypted yet, no plugin models carry this level today; the highest you can select right now is [Confidential](/privacy/tiers/confidential).

## Verifying the Environment

Because Encrypted sits on top of the TEE, the same attestation story applies: the sealed environment produces a signed statement you can verify, Nito performs a baseline verification, and the raw evidence is returned so you can complete full hardware verification yourself. The mechanics and a reference verifier are in [TEE attestation](/privacy/tee-attestation), and the verification trade-offs described for [Confidential](/privacy/tiers/confidential) apply unchanged here.

## When to Choose Encrypted

Encrypted is for the maximum assurance that nobody between your side and the sealed environment can read the data, when you can live without streaming, reasoning, tools, prompt caching, and multi-part messages. That is a narrow set of cases: the most sensitive single-shot requests where end-to-end confidentiality outweighs every convenience. For everything else, including most interactive and feature-rich work, [Confidential](/privacy/tiers/confidential) is the stronger practical choice, and it is the strongest level the plugin can select today.
