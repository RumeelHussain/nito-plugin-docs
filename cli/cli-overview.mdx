You already have this. Setup installed the **`nito` command line tool** alongside the plugin, and it is what powers `private`, session launches, and file attachments behind the scenes.

Most people never run it directly. Reach for it when you want to:

- **Install or repair** a harness integration ([`nito setup`](/get-started/install-claude-code), [`nito doctor`](/cli/doctor-and-update)).
- **Ask a question or run Fusion** without opening a chat at all ([`nito ask`](/cli/ask-and-fusion-from-terminal), [`nito fusion`](/cli/ask-and-fusion-from-terminal)).
- **Launch a session that runs through Nito** from a script or a shortcut ([`nito claude`](/cli/session-launchers), [`nito codex`](/cli/session-launchers)).
- **Keep everything current** ([`nito update`](/cli/doctor-and-update)).

<Note>
These run in your **terminal**. Plugin commands like `/nito:ask` and `$nito:ask` run **inside a Claude Code or Codex session**. Same account either way, but not the same place to type.
</Note>

## The Commands You Will Use

| Command | What it does |
| :-- | :-- |
| `nito setup <harness>` | Install and authorize a harness integration. |
| `nito ask` | Ask one question and print the answer. |
| `nito fusion` | Run one question across two or three models and print a single answer. |
| `nito claude` | Start a separate Claude Code session that runs through Nito. |
| `nito codex` | Start a separate Codex session that runs through Nito. |
| `nito doctor` | Check your install, credentials, and harness integrations. |
| `nito update` | Upgrade Nito and refresh managed integrations. |

Every command takes `--help`, so `nito ask --help` prints its exact flags and defaults.

## Global Flags

These work on any command.

| Flag | Effect |
| :-- | :-- |
| `--quiet` | Show only the answer or the value you asked for. |
| `--verbose` | Show extra execution and diagnostic detail. |
| `--no-color` | Turn off colored output, for logs and pipes. |
| `--config <path>` | Use a specific Nito config file. |
| `--version` | Print the installed version. |

## Signing In

The command line signs in through your browser, the same way the plugin does. If a command reports that you are not connected:

```text
nito agent login
```

That stores a credential in your operating system keychain. Check the active profile with `nito agent status`, and sign out with `nito agent logout`.

Nito never asks for a password in the terminal. Approval always happens in the browser.
