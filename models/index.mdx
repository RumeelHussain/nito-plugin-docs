The plugin gives you one place to reach many models. You do not hold accounts with the underlying providers, manage their keys, or learn each one's request format. You name a model, and Nito routes your call to a backend that can serve it.

## One Plugin, the Whole Catalog

Behind the plugin, Nito sits in front of many models as a single entry point. The practical result: with one sign-in you can reach the whole catalog and switch models whenever you want, without changing anything about how you work.

The model you name is a **logical model**: a stable public name that Nito maps to whichever backend can actually run it. You choose the name; Nito finds a healthy, eligible backend that serves it.

The catalog is **discovered, not fixed**. Nito adds new models and retires old ones over time, so the authoritative list is always what you see live when you browse, not a hard-coded table. Think of it like a live departures board rather than a printed timetable.

## The Tier Travels with the Model

Every model carries a privacy tier, and you get that tier by choosing that model. A more private model gives you a more private call, and the tier can never quietly weaken. This is the heart of how privacy works in the plugin: see [Tier Follows the Model](/privacy/tiers) and [The Four Tiers](/privacy/tiers).

## Browsing and Choosing

You browse and set models with commands, not config files. Run [`models`](/commands/choosing-a-model) to see the catalog for your account, `model` to set a durable default, and `--model` to override for a single call. None of this changes your host's own model. See [Choosing a Model](/commands/choosing-a-model) for the commands.
