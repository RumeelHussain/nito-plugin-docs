This page takes you from nothing to a working `$nito:ask` in Codex. It's the same shape as the Claude Code install, with one Codex-specific step: trusting the plugin's hook. You do **not** need Git, a repository checkout, or any environment variables.

## Prerequisites

- **Codex CLI** installed and working. See [Requirements](/get-started/requirements) for the minimum version.
- A **Nito account**. {/* PLACEHOLDER: link to sign-up once the URL is final. */}

## Install

<Steps>
  <Step title="Install the Nito CLI">
    The CLI powers setup, file attachments, and private/session launches.

    ```bash
    {/* PLACEHOLDER: final install command pending production release. */}
    # install the `nito` command line tool
    ```

    Confirm it's on your PATH:
    ```bash
    nito --version
    ```
  </Step>

  <Step title="Run setup for Codex">
    ```bash
    nito setup codex
    ```

    This extracts the Codex plugin, registers it as a local marketplace, and installs `nito@nito`, version-matched to your CLI. It also bundles the Private and Session hook.
  </Step>

  <Step title="Approve access">
    Setup authorizes **two credentials** and tells you so up front:

    - the **local CLI credential** (powers Private, Session, and file attachments), and
    - the **hosted connection** (powers Ask, Fusion, Models, and Status).

    For each credential that needs it, setup **opens your browser** to a Nito approval page and waits. Sign in and approve. If the browser doesn't open, setup prints a URL to visit, and you can paste the redirect URL back into the terminal. A credential you have already authorized is **skipped**. When it finishes, setup confirms the connection is logged in and prints `Nito full setup complete`.

    <Note>There is no separate authorization step to run inside Codex, setup completes the hosted authorization for you. The only remaining Codex-specific step is trusting the hook, next.</Note>
  </Step>

  <Step title="Trust the hook">
    Codex will not run a new or changed hook until you review and trust it. In Codex, run:

    ```text
    /hooks
    ```

    Review the Nito Private/Session hook and trust it.

    <Warning>
    A startup warning about the hook is **expected**. Hook trust approves **local code execution** for `$nito:private` and `$nito:session`, and is **separate from your Nito authentication**. It is not a second login.
    </Warning>
  </Step>

  <Step title="Run your first ask">
    In Codex, run:

    ```text
    $nito:ask What is the capital of France?
    ```

    You should get an answer labeled with the model and privacy level that served it.
  </Step>
</Steps>

## What Setup Just Did

- **Installed the plugin** from a local marketplace materialized from your CLI, so the CLI and plugin stay version-matched, no repo to clone.
- **Authorized the local helper and the hosted connection** as two separate credentials, approved in sequence, that the plugin selects between automatically.
- **Bundled the hook** that lets `$nito:private` intercept a prompt before Codex inference, which is why the one-time `/hooks` trust step exists.

<Note>
Codex triggers `$nito:…` commands with a `$`, not a `/`. Everywhere else the commands match Claude Code one-for-one.
</Note>
