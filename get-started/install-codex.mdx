This page takes you from nothing to a working `$nito:ask` in Codex. You do **not** need Git, a repository checkout, or any environment variables. The setup command handles all of it.

## Before You Start

- **Codex CLI** installed and working. See [Requirements](/get-started/requirements) for the minimum version.
- A **Nito account**. {/* PLACEHOLDER: link to sign-up once the URL is final. */}

## Install

<Steps>
  <Step title="Install the nito command line tool">
    It powers setup, file attachments, and private and session launches.

    ```bash
    {/* PLACEHOLDER: final install command pending production release. */}
    # install the `nito` command line tool
    ```

    Check it is on your PATH:
    ```bash
    nito --version
    ```
  </Step>

  <Step title="Run setup">
    ```bash
    nito setup codex
    ```

    This installs the Codex plugin, keeps it version-matched to your command line tool, and bundles the hook that Private and Session need.
  </Step>

  <Step title="Approve access">
    Setup authorizes **two credentials** and tells you which is which as it goes:

    - the **local credential**, which powers Private, Session, and file attachments
    - the **hosted connection**, which powers Ask, Fusion, Models, and Status

    For each one that needs it, setup **opens your browser** to a Nito approval page and waits. Sign in and approve. If the browser does not open, setup prints a URL you can visit, and you can paste the redirect back into the terminal.

    A credential you have already approved is **skipped**, so if you have signed in before you may only see one prompt.

    <Note>There is no separate step to run inside Codex. Setup finishes the hosted authorization for you.</Note>
  </Step>

  <Step title="Trust the hook">
    Codex will not run a new or changed hook until you review it. In Codex, run:

    ```text
    /hooks
    ```

    Review the Nito hook and trust it.

    <Warning>
    A startup warning about the hook is **expected**. Trusting it approves **local code execution** for `$nito:private` and `$nito:session`. It is separate from your Nito sign-in, and it is not a second login.
    </Warning>
  </Step>

  <Step title="Run your first ask">
    In Codex, run:

    ```text
    $nito:ask What is the capital of France?
    ```

    You should get an answer telling you which model served it and at what privacy level. That is the plugin working.
  </Step>
</Steps>

## What Setup Just Did

- **Installed the plugin** and pinned it to the same version as your command line tool, so the two cannot drift apart.
- **Approved two credentials** in sequence, the local one and the hosted connection. They are separate on purpose, and the plugin always tells you which one a command needs.
- **Bundled the hook** that lets `$nito:private` catch a question before Codex sends it anywhere. That is why the one-time trust step exists.

<Note>
Codex triggers commands with a `$` rather than a `/`. Everything else matches Claude Code one for one.
</Note>
