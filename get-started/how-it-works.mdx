---
title: "How It Works"
description: "What happens when you type a Nito command, and how it works without disrupting your existing workflow."
---

Type a Nito command and one call goes to Nito. Type anything else and your session behaves exactly as it always has.

## The Pieces

- **The plugin**, inside Claude Code or Codex. It gives you the Nito commands and nothing else. It does not touch the model running your session.
- **The `nito` command line tool**, on your machine. Setup installs it for you. It handles file attachments and launches private and session work.
- **Nito**, the service holding the catalog. It takes your call, sends it to a model that can serve it, and returns the answer at that model's privacy level.

## What Happens When You Type a Command

<Steps>
  <Step title="You type a Nito command in your session">
    For example `/nito:ask` in Claude Code, or `$nito:ask` in Codex.
  </Step>
  <Step title="The plugin sends that one command to Nito">
    Nothing else in your session goes with it beyond the context scope shown on the result.
  </Step>
  <Step title="Nito routes it to the model you named">
    At that model's privacy level.
  </Step>
  <Step title="The answer comes back into your chat">
    Ready to use, in the session you were already in.
  </Step>
</Steps>

## What Happens When You Don't

Ordinary messages to Claude Code or Codex behave exactly as they always have. Same model, same tools, same settings. Nothing routes through Nito unless you run a Nito command.

## You Can See What Ran

A Nito answer tells you which model served it and at what privacy level.

## If a Command Can't Run

The plugin tells you what to fix rather than failing quietly. Finish the step it names, then run your command again yourself. It will not re-send a request you would be billed for.
